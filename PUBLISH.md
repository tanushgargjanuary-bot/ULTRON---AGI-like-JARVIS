## Before you push — read the licence line

Ultron is a derivative of **FatihMakes/Mark-LVI**, licensed **CC BY-NC 4.0**.
That licence allows you to publish this, non-commercially, **with attribution**.
It does not allow selling it. Keep `LICENSE` and the attribution paragraph in
`readme.md` in place; deleting them is the one thing that makes the repo
unlawful, not the publish itself.

## The two commands (PowerShell, in the project folder)

```powershell
cd path\to\mark-jarvis
git remote add origin https://github.com/<your-account>/ultron.git
git push -u origin main
```

Create the empty repository first at <https://github.com/new>. Do not add a
README, a .gitignore or a licence there: all three already exist here, and a
second one is a merge conflict on your first push.

If GitHub asks for a password, it wants a **token**, not your Gmail password.
Create one at <https://github.com/settings/tokens> with the `repo` scope, and
paste it as the password. GitHub has not accepted account passwords for pushes
since 2021.

## What the repository will NOT contain, and why

| Excluded | Reason |
| --- | --- |
| `config/api_keys.json` | Every provider key lives in it. A public repo full of keys is a bill, not a project. |
| `memory/long_term.json` | What the assistant learned about you. Personal by definition. |
| `log.txt` | The build log. Useful to you, noisy and partly private to anyone else. |
| `verification/` | Output of one machine, regenerated by `scripts/verify.py` on every run. `verification-results.txt` stays, because it is the build record. |
| `__pycache__/`, `.venv/`, `*.bak-*` | Build noise. |

The app recreates every excluded file on first launch. A clone runs.

## What is included that matters

- `LICENSE` — CC BY-NC 4.0, and the attribution to FatihMakes.
- `.github/workflows/verify.yml` — the thing this project has never had: a
  Windows runner that executes `verify.py`, `proof_gate.py` and
  `verify_all.py` on every push. Twelve proof-gate claims say "PARTIAL — needs
  your machine". That job is the machine.
- `docs/TOOL_SUGGESTIONS.md`, `docs/LANGUAGE_DECISION.md`, `DECISIONS.md`,
  `GATEKEEPERS.md`, `HANDOFF.md` — the reasoning, the refusals, and the honest
  register of what is not proven.
- `tests/` — 1,130 tests, including the ones that exist because of a defect:
  the tool name welded into `open_appopen_app`, the refused image that was never
  recorded, the regex that froze a turn for ninety seconds.

## If the first CI run is red

Read the failing step, not the badge. The likeliest first failures are a Qt
platform plugin missing on Linux (fixed by the `apt-get` step — check the
package names against the runner image) and a `verify_all.py` check that needs
hardware a runner does not have. That second one is expected: those checks
report `SKIP` with a reason, and `SKIP` is not a failure.

A red Windows run is *information*, not embarrassment. It is the first time
those twelve claims have met a real machine.
